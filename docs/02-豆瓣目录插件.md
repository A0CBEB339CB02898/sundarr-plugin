# 豆瓣目录插件

本文档定义 `douban-catalog` 的平台映射、实现边界和验收要求。插件类型为 `CATALOG_PROVIDER`，只提供公开媒体目录补充数据，不读取想看列表、不创建传输任务，也不承担具体资源链接搜索。

## 1. 定位与参考实现

豆瓣目录是 TMDb 主目录的可选补充。实现参考 MIT 许可的 [`Marvae/douban-cli`](https://github.com/Marvae/douban-cli) 对豆瓣影视搜索、热门、分类和详情访问路径的验证，但不直接依赖或嵌入其 Node.js CLI：

```text
参考仓库：Marvae/douban-cli
参考范围：公开端点、字段语义、异常响应和访问保护
Sundarr 实现：Python CATALOG_PROVIDER
运行时依赖：只使用 Core 提供的 core.http.v1 和 core.catalog_registry.v1
不引入：Node.js 后端、运行时 Git 下载、网页执行代码、Cookie 配置
```

`thomashirtz/douban-crawler` 是批量 JSONL 抓取程序，不满足实时搜索、分页、健康检查和 Core Activation 合同，因此不作为本插件底座。

## 2. 能力映射

| Sundarr 操作 | 豆瓣公开数据路径 | MVP 行为 |
|---|---|---|
| `search` | `/j/subject_suggest` | 按关键词返回电影和剧集候选；本地执行媒体类型与年份精确过滤 |
| `trending` | `/j/search_subjects` | 使用电影或剧集的“热门”标签；无媒体类型时组合两类结果 |
| `categories` | `/j/new_search_subjects` | 电影/电视剧与题材组合为标签；热度、评分、上映时间分别映射为 `T`、`R`、`U` 排序 |
| `detail` | `/rexxar/api/v2/movie/{id}` 或 `/rexxar/api/v2/tv/{id}` | 根据明确的 `media_type` 获取详情，不跨类型猜测 |

公开接口并非正式开放 API，稳定性低于 TMDb。插件必须配置有限超时、明确错误、字段防御性解析、分页令牌校验和健康检查；失败只影响豆瓣 Provider，不得阻断 TMDb 或 Core `/health`。

## 3. 能力声明

```text
plugin_id = douban-catalog
identity_namespaces = douban.subject
media_types = movie, series
search filters = media_type, year
trending filters = media_type
categories filters = media_type, genre
categories sorts = popularity, rating, release_date
detail requires = external_id, media_type
```

MVP 不声明 `region`：现有公开分类路径没有与 Sundarr 影片来源地区完全等价且稳定的参数。搜索结果也不声明平台级排序，不能用当前页本地排序冒充完整结果排序。

题材选项使用稳定中文标签，例如剧情、喜剧、动作、爱情、科幻、动画、悬疑、惊悚、恐怖、纪录片、犯罪、奇幻、冒险和古装。未声明的题材由 Core 在调用前拒绝，插件不得静默忽略。

## 4. 数据映射

```text
external_id_provider = douban.subject
external_ids = {"douban.subject": "<subject_id>"}
media_type = movie | series
title / original_title / year / release_date
overview / genres / regions
rating / vote_count
poster_url / image_urls
rating_provider = 由 Core 设置为 douban-catalog
```

当前公开响应没有可靠的 TMDb 或 IMDb 共同 ID。插件不得生成猜测 ID，Core 也不得仅按标题、年份和类型静默合并不同 Provider 的条目。Web Console 通过 `provider_id` 显式选择 TMDb 或豆瓣；评分、详情、缓存和署名保持来源隔离。

来源署名固定声明豆瓣为数据来源，并链接豆瓣电影主页；文案不得暗示豆瓣与 Sundarr 存在隶属、合作或背书关系。能力描述通过 `image_referer_url = https://movie.douban.com/` 明确图片服务器的防盗链要求，Core 只在浏览器直连失败后的受控海报中继中使用该值。MVP 只保存外部图片 URL，不下载或长期保存海报二进制文件。

## 5. 分页与缓存

热门和分类把 Core continuation token 映射为豆瓣 `page_start`。电影与剧集混合内容使用分别记录两个偏移量的令牌；令牌必须绑定查询签名，不能挪用于其他题材、排序或媒体类型。

搜索建议接口返回量有限；结果耗尽后不伪造续页。Core 继续负责目录结果缓存、MediaSubject 最小快照和 Provider 故障降级，插件不直接访问 Redis 或 PostgreSQL。

## 6. 测试与验收

默认离线测试至少覆盖：

- Manifest 多插件解析和独立 Activation；
- 搜索字段映射、媒体类型/年份过滤和空结果；
- 电影、剧集及混合热门；
- 题材分类、三种排序映射和分页令牌防串用；
- 电影与剧集详情、字段缺失和响应结构变化；
- Core conformance runner 与显式 `provider_id` API；
- 请求失败、异常 JSON、日志与错误信息脱敏；
- 图片来源提示为 HTTPS 豆瓣电影主页，浏览器直连失败时 Core 中继可获得真实图片 MIME；
- 豆瓣候选失败时已激活插件和 Core 健康不受影响。

显式实时测试访问公开数据，至少验证关键词搜索、电影/剧集热门、题材分类、电影/剧集详情、分页、海报地址和来源署名。实时响应不得直接固化为 fixture；fixture 仅保留经人工审查的最小字段。

完整里程碑还必须完成：

1. 官方仓库 commit 发布并由 Core 锁定；
2. Core API 和启动恢复真实回归；
3. Web Console 可以显式切换 TMDb / 豆瓣，刷新和详情跳转保持 `provider_id`；
4. 禁用或破坏豆瓣后，TMDb 主目录仍然可用；
5. 插件默认测试、显式实时测试、Core 全量 pytest 和 Web 生产构建全部通过。
