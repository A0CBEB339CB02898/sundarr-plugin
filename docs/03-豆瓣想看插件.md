# 豆瓣想看插件

本文档定义 `douban-watchlist` 的公开页面映射、游标、安全边界和验收要求。插件类型为 `WATCHLIST_PROVIDER`，只响应 Core 的单次 `pull`，不自行调度、不访问数据库，也不创建传输任务。

## 1. 配置与访问边界

Manifest 只声明必填字符串 `user_id`。当前真实验证页面为公开用户想看页：

```text
https://movie.douban.com/people/{user_id}/wish
sort=time
filter=all
mode=list
type=movie | tv
start=<非负分页偏移>
```

`user_id` 必须完全由数字组成。插件固定主机、路径和查询字段，不接受任意 URL。MVP 不配置 Cookie，不访问非公开想看列表；遇到登录跳转、验证码、保护页或结构不完整时明确失败，不尝试绕过。

## 2. 为什么使用列表模式

真实页面验证显示，`mode=list` 使用 `start=0,30,60...` 翻页，并为每条有效记录提供：

- 豆瓣 subject ID；
- 收藏记录 `data-cid`；
- 加入想看日期；
- 标题、原始标题和简介文本。

列表模式不返回海报，但单页有效条目更多、无关图片和展示节点更少。插件不得为每条记录额外读取详情来补海报；Core 若已有相同 `douban.subject`，会复用既有目录快照。

## 3. 类型与游标

混合列表本身没有稳定媒体类型字段。插件分别读取 `type=movie` 和 `type=tv` 两条按加入时间降序排列的流，然后归并为统一结果；不得通过标题、时长或题材猜类型。

豆瓣分页偏移按原始槽位每次增加 30，但页面可能因为失效或隐藏条目只返回 29 项。游标因此保存：

```text
version
movie.start / movie.index / movie.done
tv.start / tv.index / tv.done
```

`start` 是当前外部分页偏移，`index` 是该页已消费的有效条目数。页内未消费完时保持相同 `start`；消费完后采用页面后页链接中的偏移。游标使用 URL-safe Base64 编码 JSON，并绑定配置 user_id，防止把其他用户或旧格式游标误用于当前实例。

每次 `pull` 最多返回 30 项；Core 的 `limit` 只作为更小的返回上限。

## 4. 字段映射

```text
external_record_id = data-cid；缺失时为 subject:<douban_subject_id>
subject.external_id_provider = douban.subject
subject.external_ids = {"douban.subject": "<subject_id>"}
subject.media_type = type=movie -> movie；type=tv -> series
subject.title = 标题链接中第一个“ / ”之前的名称
subject.original_title = 其余名称（存在时）
subject.year = 简介中的第一个有效四位年份
subject.poster_url = null
added_at = 页面加入日期，按 Asia/Shanghai 零点解释
```

## 5. 验收

- 离线 fixture 覆盖 movie / tv 归并、页内续拉、跨页、缺项、无效 cursor、保护页和重复记录。
- 公共 `run_watchlist_provider_conformance` 通过。
- 显式实时测试连续拉取至少两次，验证真实 subject ID、媒体类型、加入日期和游标推进。
- Core 首次同步入库，重复同步幂等，继续同步无重复；API / Worker 重启后游标恢复。
- `douban-catalog` 与 `douban-watchlist` 可以独立配置、启停、测试和报错。
- 不提交真实完整列表、Cookie 或未经裁剪的页面响应。
